## 2. Three Distinct Failure Modes

### 2.1 Fix P.1 — NaN Spiral (CRITICAL, 1 line fix)

**Location**: `src/memory/mem_space/layer.py:631` (Fix M-1 output-side norm clip)

**Bug**:
```python
# Line 629-633 — Fix M-1 output-side clip
_bypass_norms = bypass_h.norm(dim=-1, keepdim=True).clamp(min=1e-6)
_sd_norms = slot_delta.norm(dim=-1, keepdim=True)              # ← NO CLAMP
slot_delta = slot_delta * (_bypass_norms / _sd_norms).clamp(max=1.0)
```

When `slot_delta ≈ 0`:
- `_sd_norms → 0`
- `_bypass_norms / _sd_norms → ∞`
- `.clamp(max=1.0)` reduces ∞ to 1.0 — **but before that, `inf * 0 = nan`** in backward graph

**Compare with Fix L-1 (input side, line 529)** which correctly clamps:
```python
_m_norms = M_sel_hidden.norm(dim=-1, keepdim=True)
M_sel_hidden = M_sel_hidden * (_h_norm_ref / _m_norms.clamp(min=1e-6)).clamp(max=1.0)
```

Fix L-1 applies clamp inside the division. Fix M-1 only clamps the final product. The asymmetry is the bug.

**When does slot_delta ≈ 0?**
- `writeback_warmup_steps=500`: writeback gate activates at step 500
- NaN occurred at steps 1178–1301 (~680–800 steps after warmup activated)
- During warmup, gate is suppressed; once active at step 500, `gate_max=0.3` and writeback begins
- On tokens where the writeback gate assigns low weight (early in activation), `slot_delta` can be near-zero for some token-slot pairs
- This propagates NaN through the backward graph

**Fix P.1**:
```python
# BEFORE (line 631)
_sd_norms = slot_delta.norm(dim=-1, keepdim=True)

# AFTER (line 631)
_sd_norms = slot_delta.norm(dim=-1, keepdim=True).clamp(min=1e-6)
```

**Confidence**: very_high. This is confirmed to be a direct NaN source. Analogous to Fix L-1 which fixed the same pattern on the input side.

### 2.2 Fix P.2 — top1_sim Floor at T=1.0 (HIGH, hyperparameter change)

**Root cause**: T=1.0 is geometrically insufficient for 512-way softmax differentiation.

**Analysis**:
- With `num_slots=512`, uniform distribution = 1/512 = **0.001953**
- At T=1.0: `logits = cosine_sim * T`, logit range ≈ [-1, 1]
- Even if key spreading achieves `cos=-0.012` (confirmed on b200-2):
  - The worst slot has logit ≈ -0.012, best slot has logit ≈ +0.012
  - Logit spread = **0.024**
  - In 512-way softmax: `max_score = exp(+0.012) / (511*exp(0) + exp(+0.012)) ≈ 0.00215`
  - This is only **10% above floor** (0.001953)
  - Our criterion requires top1_sim > 0.005 at step 500 → **2.6× above floor**
  - That requires logit spread ≈ 0.6 to achieve via softmax

**Why did Fix N use T=10 originally?**
- Fix N motivation was to amplify the LM→slot_keys gradient (helps gradient reach keys)
- Fix O motivation: T=10 amplifies LM gradient 10× vs SKRL → routing collapse
- But Fix O over-corrected: T=1.0 makes routing useless even with well-trained keys

**Correct temperature analysis**:
| Temperature | LM:SKRL ratio (skrl=0.10) | Max top1_sim at cos=-0.012 |
|-------------|--------------------------|---------------------------|
| T=1.0 | 10:1 | 0.00215 (10% above floor) |
| T=5.0 | 50:1 | ~0.0028 (43% above floor) ← reasonable |
| T=10.0 | 100:1 | ~0.0033 (69% above floor) but routing collapse |
| T=20.0 | 200:1 | ~0.0038 (94% above floor) but severe collapse |

**Recommended Fix P.2**: T=5.0 as a compromise:
- LM:SKRL ratio = 50:1 (better than Fix N's 100:1 but still amplified)
- Top1_sim can reach floor+43% during early training (vs 10% at T=1.0)
- SKRL at weight=0.10 should still overcome LM gradient at 50:1

**Important**: This requires user approval as it is a hyperparameter change.

### 2.3 Fix P.3 — Memory Growth (MEDIUM)

**Location**: `src/memory/mem_space/memory_bank.py:264`

**Code**:
```python
# Non-in-place scatter (line 264)
self.slots = self.slots.scatter(1, idx_exp, updated)
```

This creates a **new tensor** for `self.slots` at every write operation, preserving the old tensor in the autograd graph.

**Why `_detach_banks` should handle this**:
`_detach_banks` correctly calls `shared_bank.detach_()` which does:
```python
def detach_(self) -> None:
    if self.slots is not None:
        self.slots = self.slots.detach()
```
This breaks the graph after each pg19 chunk.

**But**: `_detach_banks` is called **once per chunk** (line 739 of train script). Within a single chunk forward pass, all 32 layers write to the shared bank. Each write creates a new node in the autograd graph. The backward graph for one chunk has 32 scatter operations chained through the shared `self.slots` tensor.

**Memory growth hypothesis**:
- 32 layers × scatter graph nodes = 32× memory compared to a simple computation
- After writeback activates at step 500, the 32 scatter ops begin accumulating per step
- `_detach_banks` clears this at chunk boundary, but each chunk's backward holds the 32-node chain during backward pass
- With `batch_size=1, seq_len=4096, num_slots=512, slot_dim=128`: slot tensor = 512×128×2 bytes ≈ 256 KB; 32 layers × 32 scatter history nodes × 256 KB = ~250 MB per card (insufficient to explain 44 GiB growth)
- **More likely**: NaN from Fix P.1 corrupts the backward graph, causing gradient accumulation without release

**Conclusion**: Fix P.3 memory growth is likely a **side effect of Fix P.1 NaN**. Once NaN is fixed, backward graphs will be properly freed. No separate code change needed yet — monitor memory after Fix P.1 is deployed.

## 3. Evidence Triangle

### 🟢 Proposer (Best case for Fix P)
Fix P.1 is a trivial 1-line fix that directly addresses the NaN source. Fix P.2 (T=5.0) provides a 43% buffer above the 1/N floor while staying below the T=10 collapse threshold. If both are applied, we should see:
- No NaN spirals
- top1_sim reaching 0.003–0.005 by step 500
- Memory stabilizing after writeback warmup

Historical analog: Fix L-1 fixed the exact same pattern on the input side and resolved the input-side NaN issue in fix_j_ablation.

### 🔴 Skeptic (Risks)
- T=5.0 still gives LM:SKRL ratio = 50:1. At step 1000+, this may again pull toward routing collapse depending on what loss landscape the model settles into.
- The memory growth of 44 GiB/card is too large to explain by scatter graph nodes alone. If there is another accumulation source (e.g., activation checkpointing, hidden state copies), it will persist after Fix P.1.
- Fix P.1 NaN might not be the only NaN source. The SKRL reward computation in selector.py may also have similar stability issues under extreme routing concentrations.

### 🔵 Critic (Blind spots)
- We do not have a confirmed stack trace from the NaN onset step. The `nan_onset_step=1178` is from diagnostic metrics, not a full traceback. There could be a different NaN source that Fix P.1 does not address.
- The "10% above floor" calculation for T=1.0 assumes cos=-0.012 (Fix O b200-2 maximum achieved). If SKRL can push cos to -0.1 or lower with enough steps, T=1.0 would become sufficient. We killed the run too early to know the asymptote.
- Fix P.2 (T=5.0) recommendation is based on geometric analysis, not empirical validation. We may need an ablation of T=2, T=5, T=8 to find the sweet spot.
