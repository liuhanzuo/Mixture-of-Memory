## Q1 — Memory Growth Root Cause

### Finding: Non-in-place scatter + M_sel_slot_soft over 512 live-graph slots builds an unbounded chain

**Evidence chain:**

1. `memory_bank.py:264`:
   ```python
   self.slots = self.slots.scatter(1, idx_exp, updated)
   ```
   This is **non-in-place** `scatter`. It creates a NEW tensor whose `grad_fn` holds a reference to the OLD `self.slots`. After each write, `self.slots` = new tensor pointing back to prev tensor.

2. `layer.py:512-516` (M_sel_slot_soft, Fix J-A removed the `.detach()`):
   ```python
   M_sel_slot_soft = torch.einsum("bn,bnd->bd", scores, slots)  # slots has grad_fn
   ```
   The einsum over ALL N=512 slots includes the full slot tensor with its accumulated grad chain.

3. With `shared_memory_bank=True`, all 32 `MemorySpaceLayer` instances share ONE `MemoryBank` object. Each layer writes to it (32 writes per forward pass), each write creates a new `scatter` node. Per-chunk autograd graph depth = 32 writes × num_chunks_processed. Without a proper inter-chunk break, this compounds.

4. `_detach_banks` is called at train_script:739 between chunks:
   ```python
   def _detach_banks(model):
       shared_bank.detach_()   # line 225
       for w in ...: w.memory_bank.detach_()  # line 231
   ```
   But the shared bank is registered via `object.__setattr__(self, "memory_bank", shared_bank)` (layer.py:256-257), bypassing nn.Module's submodule registry. If `_detach_banks` iterates `model.modules()` to find MemoryBank instances, it will NOT find the shared bank through normal submodule traversal — it is invisible to `model.modules()`. The script appears to handle this with a direct reference, but any code-path that misses the shared bank results in the chain accumulating.

**Conclusion:** The scatter chain accumulates across chunks (32 writes × n_chunks deep), and M_sel_slot_soft backward through all 512 live-graph slots amplifies the backward graph. Memory growth 79.8→124 GiB/card is consistent with ~5-10 chunks of accumulated depth before OOM/NaN.

## Q2 — NaN Spiral Root Cause

### Primary: Fix M-1 division-by-zero bug at layer.py:631-632

```python
# layer.py lines 630-632:
_bypass_norms = bypass_h.norm(dim=-1, keepdim=True).clamp(min=1e-6)
_sd_norms = slot_delta.norm(dim=-1, keepdim=True)                    # ← BUG: no clamp!
slot_delta = slot_delta * (_bypass_norms / _sd_norms).clamp(max=1.0)
```

**The bug:** `_sd_norms` is NOT clamped before being used as the denominator. When `slot_delta ≈ 0` (common during early writeback warmup, or when the bypass and extended outputs nearly cancel), `_sd_norms → 0` and the division `_bypass_norms / _sd_norms → +inf`. The subsequent `.clamp(max=1.0)` does NOT help because `+inf.clamp(max=1.0) = 1.0` — but the intermediate `inf` propagates through `grad_fn` of the division op. On the backward pass, `d(inf)/d(slot_delta)` produces NaN gradients.

More precisely:
- `slot_delta = slot_delta * scale` where `scale = (_bypass_norms / _sd_norms).clamp(max=1.0)`
- If `_sd_norms = 0` exactly: `0/0 = NaN` (IEEE 754), `.clamp(max=1.0) = NaN`, `slot_delta * NaN = NaN`
- If `_sd_norms = ε` (very small, representable in bf16): `_bypass_norms / ε = inf`, `.clamp(max=1.0) = 1.0`, FORWARD is OK, but `d(clamp)/d(ε)` in backward involves large gradients that can overflow bf16 range (±3.4×10^38)

**Why it triggers at steps ~1178/1301:** During writeback warmup (first 500 steps), β≈0 so slots change slowly. Around step 500-1300 the gate opens and larger updates begin flowing. Some tokens produce small `slot_delta` as the model adjusts, triggering the near-zero norm division.

### Secondary: SKRL gradient explosion when slot_keys → small norm

`slot_key_diversity_loss` at selector.py:305:
```python
nk = F.normalize(self.slot_keys, dim=-1)  # [N, S]
```
`F.normalize` has gradient `d/dx = (I - n n^T) / ||x||`. If slot_keys shrinks toward 0 (e.g., via aggressive gradient descent on SKRL), the `1/||x||` term explodes. At std=0.1 initial norm of `~sqrt(128)*0.1 ≈ 1.13`, this is safe at init, but sustained SKRL + LM gradient interplay can erode norms below safe range. This is a secondary contributor; the Fix M-1 bug is the primary trigger.

## Q3 — top1_sim Floor Root Cause

### Finding: Fix O temperature T=1.0 is insufficient to differentiate 512-way softmax

`selector.py:146-155`:
```python
q = F.normalize(self.Q_sel(pool_of_H), dim=-1)          # unit vector
k = F.normalize(self.slot_keys.unsqueeze(0)..., dim=-1)  # unit vectors
logits = torch.einsum("bs,bns->bn", q, k) * self.temperature  # cosine_sim * T
scores = F.softmax(logits, dim=-1)
```

At **T=1.0**:
- `slot_keys` initialized with std=0.1 → typical cosine similarity between key_i and query ≈ 0.01–0.05
- SKRL loss running: after partial training, pairwise cos ≈ oscillating near 0 (per Fix N finding)
- Logit range = cosine_sim_range × T = ~0.1 × 1.0 = 0.1
- 512-way softmax with max logit difference 0.1: `softmax_max ≈ e^0.1 / (e^0.1 + 511*e^0) = 1.105 / (1.105 + 511) ≈ 0.00215`

This is barely above the 1/N = 1/512 ≈ 0.00195 uniform floor. The max softmax score ≈ 0.00215 — only 10% above uniform. This explains top1_sim ≈ 0.001968 ≈ 1/512 throughout training.

**This is NOT a Q_sel training issue** — Q_sel does have gradients (it is a proper `nn.Linear`, NOT frozen, IS in optimizer). The problem is purely geometric: at T=1.0 the signal-to-noise ratio of the softmax is too low to produce meaningful routing.

**Comparison:**
- At **T=10.0** (pre-Fix-O): logit range = 10 × 0.1 = 1.0 → softmax_max ≈ e^1 / (e^1 + 511) ≈ 0.0053 — 2.7× above uniform; routing is possible
- At **T=1.0** (Fix O): logit range = 0.1 → barely above uniform — routing degenerates

**Root of the root:** Fix O was motivated by Fix N finding that T=10 amplified LM gradient 10× relative to SKRL. But the correct fix was to increase SKRL weight to compensate, NOT to lower T to 1.0. T=1.0 makes routing impossible even when SKRL successfully diversifies slot_keys.

**Q_sel detach status:** `q = F.normalize(self.Q_sel(pool_of_H), dim=-1)` — no detach, Q_sel IS trained, IS in optimizer. This is correct. The issue is purely temperature.

## Fix P Proposal

Three concrete changes, ordered by severity:

### Fix P.1 — CRITICAL: Fix M-1 division-by-zero (NaN source)
**File:** `src/memory/mem_space/layer.py`  
**Lines:** 630-632  
**Current:**
```python
_bypass_norms = bypass_h.norm(dim=-1, keepdim=True).clamp(min=1e-6)
_sd_norms = slot_delta.norm(dim=-1, keepdim=True)
slot_delta = slot_delta * (_bypass_norms / _sd_norms).clamp(max=1.0)
```
**Fix:**
```python
_bypass_norms = bypass_h.norm(dim=-1, keepdim=True).clamp(min=1e-6)
_sd_norms = slot_delta.norm(dim=-1, keepdim=True).clamp(min=1e-6)  # Fix P.1: prevent div-by-zero
slot_delta = slot_delta * (_bypass_norms / _sd_norms).clamp(max=1.0)
```
**Why:** Mirrors exactly the pattern from Fix L-1 (input side) which correctly clamps `_h_norm_ref.clamp(min=1e-6)`. The `min=1e-6` is far below any real bf16 representable norm (bf16 minimum ~6e-39), so it only activates when slot_delta is numerically zero — exactly the case we need to protect.

### Fix P.2 — HIGH: Restore temperature to ≥5.0 (top1_sim stuck)
**File:** `src/memory/mem_space/selector.py`  
**Line:** 88 (constructor), plus `MemorySpaceConfig.selector_temperature`  
**Current:** `temperature: float = 1.0` (Fix O set this)  
**Fix:** `temperature: float = 5.0` (or configurable via CLI, already supported via `--selector_temperature`)

**Justification:**
- At T=5.0, logit range ≈ 0.5 → softmax_max ≈ e^0.5/(e^0.5+511) ≈ 0.0032 — 1.6× above 1/N, routing begins
- At T=10.0, routing is 2.7× above 1/N — better routing but original SKRL-LM imbalance issue
- **Recommended: T=5.0** as a middle ground — enough routing signal without overpowering SKRL

**Alternative approach (preferred if running ablations):** Keep T=1.0 but increase SKRL weight to 0.20–0.50 to make cosine differences larger (e.g., mean_pairwise_cos → -0.01), then T=1.0 produces logit range 0.2+ and routing emerges. This avoids the LM-SKRL imbalance issue of T=10.

### Fix P.3 — MEDIUM: Ensure _detach_banks reaches shared bank reliably
**File:** `scripts/train_mem_space_pg19.py`  
**Lines:** ~220-231 (`_detach_banks` function)  
**Current behavior:** Shared bank registered via `object.__setattr__`, potentially invisible to module iteration  
**Fix:** Verify (and if needed, fix) `_detach_banks` explicitly accesses the shared bank object by direct reference (not via `model.modules()` iteration), OR add `assert` to verify `shared_bank.slots is not None and not shared_bank.slots.requires_grad` after detach.

The key check is whether `_detach_banks` at line 225 accesses the bank via a variable that was captured at setup time (before the `object.__setattr__` call) — if it does, it's correct. If it tries to find it via `model.modules()`, it will fail silently because `object.__setattr__` bypasses `nn.Module.__setattr__` and the bank never appears in `_modules`.
