## 2. Root Cause Analysis

### 2.1 The Gradient Competition — Why SKRL Is Cancelled

**SKRL gradient path** (repulsion, pushing keys apart):
```
slot_key_diversity_loss → F.normalize(slot_keys) → slot_keys
grad direction: orthogonal-away from all neighbor keys on S^127
magnitude: O(1), temperature-independent
```

**LM gradient path** (attractor, pulling keys together):
```
lm_loss → next_hidden → M_sel_hidden_soft → einsum(scores, slots) 
       → softmax(logits) → logits = einsum(q, k) * T 
       → k = F.normalize(slot_keys) → slot_keys
grad direction: toward configurations that cluster keys for LM prediction
magnitude: scales with T (higher T → larger LM grad to slot_keys)
```

These two gradients act on the same parameter (`self.slot_keys`) in opposing directions. The LM gradient wants keys to cluster so the softmax can route to useful slots. SKRL wants keys to spread. They equilibrate around zero — hence the oscillation.

### 2.2 Why the Analysis in fix_p_analysis.md Was Wrong

The fix_p researcher (2026-04-29 21:29) concluded that T=5.0 would give a "43% buffer above floor". This was correct for the *routing* metric given a fixed key distribution. But it missed the critical question: **does SKRL have enough gradient to actually drive key separation?**

The fix_p analysis computed LM:SKRL gradient ratio as 50:1 at T=5.0. But this ratio is **irrelevant to whether SKRL wins**: both forces act on slot_keys simultaneously, and since there are 32 layers, each with independent slot_keys, the total LM gradient to any one layer's slot_keys accumulates from all 32 layers' LM losses passing through that layer's STE path. The SKRL gradient to any one layer's slot_keys comes only from that layer's SKRL loss. Result: the LM side is systematically stronger at every temperature, and can always overpower SKRL regardless of T.

### 2.3 The Structural Bug: slot_keys Is on the LM Gradient Path

**File**: `src/memory/mem_space/selector.py`, line 154:
```python
logits = torch.einsum("bs,bns->bn", q, k) * self.temperature
```

Here `k = F.normalize(self.slot_keys, ...)` is used to compute logits, and these logits feed into softmax scores, which feed into `M_sel_hidden_soft` (via the STE path in layer.py line 507–522), which propagates LM loss gradient back to `slot_keys`.

**The slot_keys parameter was designed to be "address labels" trained purely by routing diversity losses** (Fix B docstring: "decoupling slot addressing from slot content"). But by using `k` (which has gradient to slot_keys) in the logit computation, slot_keys ends up on the LM gradient path.

The LM gradient through this path pulls slot_keys toward configurations where similar queries consistently find the same slot (clustering), while SKRL pushes in the opposite direction (spreading). They cancel, producing the observed oscillation.

### 2.4 Why Previous Fixes Did Not Catch This

- **Fix B** introduced slot_keys as a learnable parameter. Did not detach it from LM path.
- **Fixes C–F** tried various routing losses but all assumed SKRL would dominate. Never audited whether LM gradient was flowing through k.
- **Fix G (SKRL)** was designed to break the deadlock by acting on slot_keys directly. Correct diagnosis of the deadlock, but missed that LM gradient still reaches slot_keys through the logit computation.
- **Fix N** (T=10 fix) and **Fix O** (T=1.0) and **Fix P** (T=5.0) all assumed temperature was the variable to tune. Temperature is a multiplier on the LM gradient magnitude to slot_keys, not a fix for the competition structure.

## 3. Fix Q Specification

### Fix Q.1 — Detach k from LM Gradient Path (1 line)

**File**: `src/memory/mem_space/selector.py`  
**Line**: 154

```python
# BEFORE:
logits = torch.einsum("bs,bns->bn", q, k) * self.temperature

# AFTER (Fix Q.1):
logits = torch.einsum("bs,bns->bn", q, k.detach()) * self.temperature
```

**Mechanism**: `k.detach()` stops gradient from flowing from `logits` back through `k` to `slot_keys`. After this change:
- `slot_keys` receives gradient ONLY from `slot_key_diversity_loss` (SKRL)
- `Q_sel` still receives LM gradient through `q` (unchanged), so the query learns to find useful slots
- The LM-vs-SKRL competition on `slot_keys` is eliminated

**What changes at the routing level**: 
- Forward pass: identical (k values unchanged)
- Backward to slot_keys: SKRL gradient only, monotonically pushing toward negative cos
- Backward to Q_sel: LM gradient through q (as designed)
- Backward to slots (content): unchanged — still flows through STE via M_sel_hidden_soft

**Expected trajectory after Fix Q.1**:
- mean_pairwise_cos should decrease monotonically (not oscillate)
- Rate depends on SKRL weight. At skrl_weight=0.10, 32 layers × SKRL ≈ strong signal
- top1_sim should begin rising once cos is sufficiently negative (logit separation)

**Confidence**: very_high. The oscillation is a direct signature of gradient cancellation on slot_keys. Detaching k eliminates the LM path to slot_keys. This is a 1-line change with no forward-pass effect.

## 4. Triangular Analysis

### 🟢 Proposer (Best case for Fix Q.1)

Fix Q.1 is the minimal correct fix for the structural gradient competition. The oscillation pattern (cos ±0.01, never descending) is a textbook sign of two competing gradient sources on the same parameter. Once the LM path is detached from k, SKRL is unopposed on slot_keys. With 32 layers each contributing skrl_weight=0.10 × SKRL_loss, the effective gradient per step is 32× what the fix_p researcher estimated for a single layer. Keys should converge to a maximally-separated configuration on S^127 within hundreds of steps. Fix B's architectural intention ("address labels decoupled from slot content") is finally realized. Q_sel still learns from LM loss through q — the routing *query* remains useful.

Historical analog: Fix J-A removed `detach(slots)` in the STE path (layer.py line 509) to allow LM gradient to reach slot content. Fix Q.1 adds back a detach on `k` to protect slot_keys from the same gradient. The pattern is: add detach where a parameter should learn from a targeted signal only.

### 🔴 Skeptic (Risks)

1. **Will Q_sel alone be enough for routing?** After Fix Q.1, `Q_sel` is the only bridge between LM loss and routing quality. Q_sel learns to project the query into a space where the fixed (SKRL-trained) slot_keys are informative. This is a harder learning problem: the slot_keys geography is now determined by SKRL geometry alone, and Q_sel must adapt to that geometry. If SKRL converges to a near-uniform spread on S^127, Q_sel will need to learn complex projections to find relevant slots.

2. **SKRL geometry vs LM-useful geometry**: SKRL maximally spreads keys on S^127 (uniform distribution on sphere). But the optimal routing may require keys to be clustered in semantic "neighborhoods" (e.g., factual vs stylistic vs syntactic). By detaching, we sacrifice LM-guided key organization. The routing may become geometrically diverse but semantically arbitrary.

3. **Temperature scaling of LM gradient to Q_sel**: After Fix Q.1, LM gradient still flows through `q` to Q_sel. The magnitude of this gradient still scales with T. If T=5.0 makes Q_sel training too aggressive relative to SKRL, we might see Q_sel overfitting to a few dominant keys (routing collapse through the query side rather than the key side).

4. **SKRL gradient accumulation**: With 32 layers contributing to total_SKRL, the effective skrl_weight on any single layer's slot_keys might be too large (32 × 0.10 = 3.2 effective weight). This could cause keys to spread too aggressively and overshoot the max-entropy configuration, destabilizing LM training.

### 🔵 Critic (Blind spots)

1. **No NaN root-cause confirmation**: The NaN spirals in fix_p_ablation (node0 step 970, node2 step 880+) are not confirmed to be from Fix P.1 (the _sd_norms clamp). The clamp was applied. But new NaN sources may exist if SKRL gradient to slot_keys becomes very large after detach removes the opposing LM gradient.

2. **Oscillation could be a batch-effect, not gradient competition**: The cos values are computed on only 256 random pairs from layer-0. The oscillation ±0.01 is within the noise floor for 512 keys × 128-dim. We cannot rule out that SKRL IS making slow progress (e.g., at rate -0.001/100 steps) but this progress is masked by diagnostic noise.

3. **The 32-layer summation assumption**: We inferred that each layer's slot_keys gets gradient from all 32 layers' LM loss. But the STE path gradient to slot_keys is: `lm_loss → layer_i_hidden → M_sel_hidden_soft_i → scores_i → logits_i → k_i → slot_keys_i`. Each layer's slot_keys only receives gradient from *its own* STE path. The 32-layer argument is about *total SKRL* being stronger in aggregate, not about LM being stronger per-layer. The competition is still per-layer (one LM path vs one SKRL path per layer), not 32:1.

4. **Q_sel convergence may be faster than SKRL**: If Q_sel converges before SKRL has spread the keys, the model may settle into a state where Q_sel selects a fixed small subset of keys consistently (even with diverse keys), effectively implementing slot collapse through the query side.
