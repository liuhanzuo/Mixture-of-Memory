## 3. 这一轮实验的关键结论：chunk_query 修复**失败了**（重要！）

### 我做了什么
原 selector 用 **max-pool over T=1024 tokens** 算 query：每个 slot 都能找到一个"冠军 token"，导致所有 slot 的 max-logit 都差不多 → softmax 退化成均匀。我加了一个 `routing_pool_mode=chunk_query` 开关，改成 **mean-pool → 单一 chunk query**，想打破这个结构性上限。

改动文件（已在本地，**未 commit**）：
- `src/memory/mem_space/config.py` — 加 `routing_pool_mode` 字段
- `src/memory/mem_space/selector.py` — forward 支持 chunk_query 分支
- `src/memory/mem_space/layer.py` — 把 config 接到 selector
- `scripts/train_mem_space_dolmino_cpt.py` — 加 `--routing_pool_mode` CLI
- `scripts/launch_p1v3_chunk_query.sh` — 启动脚本

### 结果：同样塌缩，只是机制不同
remote chunk_query 的 `top1_sim` / `per_tok_logit_std` 轨迹（实测）：

| step | top1_sim | per_tok_logit_std | retrieved_norm |
|------|----------|-------------------|----------------|
| 4    | 0.028    | 0.57              | 0.45（slot 初值≈0）|
| 18   | 0.028    | 0.56              | 0.47 |
| 35   | 0.016    | 0.40              | 5.0（slot 长大了）|
| 75   | 0.0099   | 0.11              | 0.42 |
| 299  | 0.0098   | 0.066             | 5.0 |

`per_tok_logit_std` 从 0.57 单调衰减到 0.066 → logits 几乎全相等 → 又退化成均匀。

### 根因（接手的人务必理解这一点）
- 初期有信号**纯粹是因为 slot 初始 norm≈0**，content-based routing 此时有区分度；
- 一旦 slot 通过 EMA writeback 长到 norm≈5.0，`K_sel(slots)` 投影后所有 key 从 query 视角看变得几乎一样；
- **mean-pool 把 1024 个异质 token 平均成一个"万金油" query**，对任何 slot 的打分都差不多 → 无法区分。
- 注意 `key_max_cos` 一直稳定在 0.38~0.56，说明 **key 在原始空间没塌缩**，塌缩发生在"query 太泛化"这一侧。

**结论：max-pool 和 mean-pool 都不行。任何"把整个 chunk 压成单一向量再去查 slot"的方案都会塌缩。** 这跟 `ops/research_notes/20260430_1106_fix_z_analysis.md` 里记录的 "query collapse" 是同一个病。

## 4. 下一步建议方向（按我的推荐优先级）

我倾向 **方向 1**，但这需要和用户确认（属于架构层面的改动，不是单纯调参）。

1. **Multi-query routing（最推荐）**：不要把 chunk 压成 1 个 query。用 L3 summary 的 64 个压缩 token 作为 **64 个独立 query**，每个 query 各自 top-k 选 slot，再合并。保留了 chunk 内部的多样性，避免"万金油 query"。L3 模块已经存在（`--use_l3_summary`，已在跑）。

2. **Cross-attention routing**：反过来，让每个 slot 作为 query 去 attend 整个 chunk 的 hidden states，自己算 relevance 分数。slot 主动找"我关心的 token 在不在这个 chunk 里"。

3. **放弃 content-based routing**：用 position/hash 把 token 段确定性地分配到 slot（类似 Infini-attention 的分块）。简单、不会塌缩，但放弃了"按内容寻址"的初衷。

### 防塌缩的通用补丁（无论选哪个方向都该加）
- slot value 已有 `slot_value_norm_cap=5.0`，但塌缩发生在**投影空间**。考虑对 `K_sel(slots)` 输出做 LayerNorm，或对 query/key 都 normalize 后再点积（当前已 normalize，但 mean-pool 后的 query 模长信息丢了）。
- 可以加一个**早期 routing 监控早停**：如果 `per_tok_logit_std` 连续 N 步 < 0.15，自动判失败、kill、换方向，别浪费 GPU 跑满 2000 步。

## 5. 关键诊断指标速查（怎么判断 routing 是否健康）

`WRITEBACK_DIAG` 行：
- `gate_val(beta)` / `inject_gate_mean`：如果一直钉在初值不动 → routing 没给有效梯度（是结果不是病因）
