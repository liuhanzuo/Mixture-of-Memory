\begin{abstract}
A transformer processes its input in two phases along \emph{depth}: the lower
layers build a semantic representation of the text, and the upper layers turn it
into a next-token prediction. Building on this, we propose \textbf{CoMem}
(Comprehension Memory): split the network at a middle layer $j$, run each context
chunk only through the lower layers $[0{:}j]$, and cache the single depth-$j$
hidden that summarizes it; at read time, retrieve the top-$k$ relevant chunk
hiddens and recompute only the upper layers $[j{:}L]$. The split $j$ is fixed
empirically by probing and split-depth sweeps ($\approx$$0.33$--$0.40$ of the
stack, e.g.\ layer $12/36$ on Qwen3-8B) and holds across model families,
including an 80-layer Mixture-of-Experts. The cached memory is only
$\approx$$1/72$ of a full KV cache, and read compute and memory are
\emph{constant} in context length ($\approx$18\,GB, vs.\ a full model's
$\approx$89\,GB at 128k), giving up to $7.83\times$ faster prefill at 128k.
Because the read pack stays inside the native
window, CoMem is the only method usable past the extrapolation limit---at 128k,
full-context inference collapses to 0 on RULER while CoMem holds 100---and, with
a light self-distilled adapter, matches dense inference inside the window while
far exceeding prior fixed-memory methods. Long-context memory is a
layer-partition problem, not a token-budget problem.
\end{abstract}
