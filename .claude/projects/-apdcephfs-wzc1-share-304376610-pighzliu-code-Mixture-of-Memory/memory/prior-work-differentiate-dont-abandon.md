调研/选题时**不要因为存在类似工作就放弃一个方向**。判定标准是"是否完全相同、是否抄袭"，而不是"是否有重叠"。只要和已有方法**存在区别（区别大小不重要）**，就可以作为独立工作。

**2-3 个月内发表/预印的工作视为同期工作（concurrent）**，这一点上要更放松，同期工作不构成 preemption。

**更进一步：主动把已有工作当成 follow-up 的起点。** 找它们的缺陷、没覆盖的情形、方法上的问题，然后通过修改去修正/提升——这样得到的 idea 同样是好 idea，有时比"全新方向"更可靠。

**Why**：我之前在 dllm 方向的调研把 SotA scan 当成"查重"而不是"选题"，subagent 一报"DreamOn 吃掉了 length-elastic"我就只留下唯一一条没被占的路去执行，把整个方向做窄了。派出的 workflow 里更是写死了 `novelty === 'fully-preempted' → drop` 的硬杀规则，且 verify prompt 第一句就是"默认它已经被做过了，努力找到杀死它的论文"——这是把过度保守机制化了。

**How to apply**：
- verify/novelty 阶段的产出不应是"生/死"，而应是**差异化定位 + follow-up 机会**：这篇覆盖了什么、留了什么口子、它的缺陷是什么、我们改什么能修正它
- 只有**逐字同题同法**才判 drop；有重叠 → 输出"如何差异化"而非丢弃
- 日期检查：目标会议截止日前 2-3 个月内的工作标为 concurrent，不计入 preemption
- 主动增设一类候选来源：「某已有工作的缺陷修正/扩展」
- 与 [[venue-verify-must-use-openreview-2026]] 配合：venue 核实仍要严格（判断是否 concurrent 需要准确日期），但**核实结果用于定位，不用于劝退**

## ★★ 2026-08-12 用户强化：印证+组合本身就是贡献，不是缩减的理由

用户原话：**「小的点被抢走了并不意味着我们需要 narrow。相反我们的论文如果印证了他们每篇的观点并组合起来反而是我们的优势」**

### 我犯的错（A04 RELATED_WORK.md）

我做了一次 novelty 审计，产出一份 11 条 must-NOT-claim 清单，然后**把它转写成了 scope 上限**：写下「A04 must be renamed and **narrowed**」「顶多值 short paper 或 methods section」。

**这是两个不同的动作，我把它们混成了一个：**
- 审计的正确产出 = **引用义务清单**（这些点归功于别人）
- 我实际写出的 = **贡献天花板**（因此我们的价值很小）

「不能声称首创」**不蕴含**「贡献很小」。这一步滑坡没有任何逻辑依据。

### 正确的框架：跨独立模态的收敛证据

A04 的例子：六篇论文各自在**不同损伤模态**上报告「代理指标失效」——
N3 完好模型/理论证明、N4 量化/SAE 特征、N2 test-time training、C2 层剪枝+SFT、N5 压缩/BERT 分类。

**关键：没人证明过这些是同一个现象。** 六个互不相关的作者群、六种损伤、六把**互不可比的尺子**。

于是真正的论文主张是：
> 六篇独立工作分别报告代理指标在各自模态下失效；**我们证明这是同一个可测量的现象，并给出裁决它的判决程序。**

我们提供的正是那六篇都缺的：共同的测量（null-calibrated residual）、共同的判决规则（预注册非劣性检验）、run-level 方差（C1/C2/C3/N1 一篇都没报 seed）。

### 为什么这个框架更好防守，不是更难

每一条 corroboration 都是**「有文献支持的预测被我们证实」**，而不是一个需要我们独自扛的新主张。反过来若我们的数据**反驳**了其中某篇，那同样是发现。**两个方向都有产出** —— 这是设计上的稳健，不是运气。

### 规则

1. novelty 审计**只准**输出引用义务 + 差异化定位。**禁止**输出 scope 上限、「顶多值 X」、「必须 narrowed」。
2. 发现 N 篇相关工作时，先问：**它们彼此之间是否已经互相印证过？** 如果没有（通常没有，因为分属不同子领域/不同尺子），那么"让它们可比"本身就是贡献。
3. 「我们印证了 X 并把它扩展到 Y 模态」是**正当且强**的论文段落，不是弱化。
4. 判死一个方向只能靠**实验证伪**（kill gate 触发），不能靠文献计数。
