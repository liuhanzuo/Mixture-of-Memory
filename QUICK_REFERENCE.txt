🤖 AGENT ARCHITECTURE
════════════════════════════════════════════════════════════════════════════

CronCreate (every 20 min)
    ↓
  /heartbeat (main session)
    ├─ Step 0: Check PENDING_TASKS.md
    ├─ Step 1-5: GPU status, remote cluster, requests, training, issues
    ├─ Step 6: Dispatch researcher/coder (async)
    └─ Update state files (append + write semantics)

/heartbeat can autonomously:
  ✓ Kill PPL > 100 training
  ✓ Kill stalled runs
  ✓ Auto-launch tasks (auto_launch=true)
  ✓ Dispatch /researcher and /coder
  ✓ Execute researcher-confirmed hyperparameter changes
  ✓ Decide next steps (close experiment loop)

/heartbeat CANNOT:
  ✗ Kill healthy training
  ✗ Self-approve TRAINER_REQUESTS
  ✗ Self-execute without researcher confirmation
  ✗ Wait after experiment completion
  ✗ Leave GPU idle + pending tasks

Subagents (/researcher, /coder):
  ├─ Dispatched by heartbeat (or user)
  ├─ Result appended to RESEARCHER_REPORTS.jsonl / ISSUES.jsonl
  ├─ Confidence: high/medium/low
  ├─ high/very_high confidence → auto-execution allowed
  └─ No user feedback needed

🎓 KEY LEARNINGS
════════════════════════════════════════════════════════════════════════════

1. **No Hybrid State**: CLAUDE.md explicitly forbids "Co-Authored-By: Claude"
   → Your CI/CD must detect and reject these

2. **Forced Closure**: Heartbeat MUST decide next step immediately (no waiting)
   → LLM-powered agent loops need strong accountability

3. **Isolation by Design**: Parallel algorithms need config namespacing
   → Your multi-coder dispatch needs namespace awareness

4. **Append-Only Safety**: Correction lines instead of edits prevent conflicts
   → Consider this for distributed CI/CD logging

5. **PPL as Signal**: PPL>100 = model broken (not just bad retrieval)
   → Your LLM code review needs domain knowledge about failure modes

6. **Version Docs Mandatory**: Every architecture change → versions/vN_*.md
   → Your code review should enforce architecture documentation

7. **Heartbeat IS Main**: No background entity waiting; each session is fresh
   → Your orchestration can be stateless + request-driven
