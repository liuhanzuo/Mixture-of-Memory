# 深度分析报告模板

> 本文件定义 Agent 生成 Markdown 报告时如何落地 [Taiji Design 设计规范](./Taiji_Design_Spec.md)。
> Agent 生成报告时**必须严格按照本模板逐字段填充**，不得自行增删章节、修改表格列名或改变措辞。

---

## 1. 颜色标记规则

颜色通过 `<span style="color:...">` 内联样式实现。

| 指标 | 区间 | 颜色 | 示例 |
| :--- | :--- | :--- | :--- |
| ACC / bon_acc / pass@k | ≥ 80% | `#00A854` | `<span style="color:#00A854">100.00%</span>` |
| | 50% ~ 80% | `#FA8C16` | `<span style="color:#FA8C16">64.67%</span>` |
| | < 50% | `#E54545` | `<span style="color:#E54545">36.69%</span>` |
| Error Rate | = 0% | `#00A854` | `<span style="color:#00A854">0.0%</span>` |
| | > 0% ~ 5% | `#FA8C16` | `<span style="color:#FA8C16">0.40%</span>` |
| | > 5% | `#E54545` | `<span style="color:#E54545">8.50%</span>` |
| 截断率 | = 0% | `#00A854` | `<span style="color:#00A854">0.0%</span>` |
| | > 0% | `#E54545` | `<span style="color:#E54545">2.75%</span>` |

## 2. 模板选择与标题层级

### 模板选择

根据分析对象选择报告模板：

| 分析对象 | 使用模板 |
| :--- | :--- |
| 单个 Task，或单模型视角的 Insight | [3.A Task 分析报告模板](#3a-task-分析报告模板) |
| 多个模型横向对比（多条 Task 记录，一份报告） | [3.B 多模型对比报告模板](#3b-多模型对比报告模板) |

> ⚠️ 下文代码块内的 `#` / `##` / `###` 是**报告正文**的标题层级，与本文件的章节编号（1、2、3…）是两套独立体系，不要混淆。

### 报告正文标题层级

| Markdown | 用途 |
| :--- | :--- |
| `#` | 报告标题（唯一，格式固定见下方） |
| `##` | 一级章节 |
| `###` | 二级章节 |
| `####` | 三级小节（一般不用） |

> Task 报告一级章节：1.总体概览 / 2.各评测集详细分析 / 3.Badcase归因分析 / 4.建议与改进方向
> 多模型对比报告一级章节：1.总体对比概览 / 2.分歧Case对照分析 / 3.共性失败Case / 4.模型优劣总结 / 5.选型建议

## 3. 报告结构模板（必须逐字段填充，不可增删章节）

### 3.A Task 分析报告模板

> 适用于单个 Task 分析，或聚焦单模型表现的 Insight 分析。以下代码块内即为报告正文模板，`{}` 为待填字段：

```
# {Task ID / Insight名称} 模型表现深度分析报告

> **分析时间**: {YYYY-MM-DD}
> **目标**: {Task {id} / Insight {id} ({name})}
> **分析类型**: {EVAL_TASK / INSIGHT}
> **模型**: {模型名称，保留完整名称，不截断}

---

## 1. 总体概览

### 1.0 评测集汇总表

| 评测集 | ACC | bon_acc | Error Rate | 截断率 | 题目数 | 平均Comp Token | 平均Prompt Token |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| {名称} | {颜色标记} | {颜色标记} | {颜色标记} | {颜色标记} | {N} | {N} | {N} |

### 1.1 关键指标摘要

| 指标 | 数值 |
| :--- | :--- |
| 总评测集数 | {N} |
| 最高 ACC | {颜色标记} |
| 最低 ACC | {颜色标记} |
| 整体加权平均 ACC | {约值} |
| 零分 Badcase 总数 | {N} |

---

## 2. 各评测集详细分析

### 2.{序号} {评测集名称} (ACC: {颜色标记})

- **题目数**: {N} | **通过**: {N} | **失败**: {N} | **错误**: {N}
- **Badcase 数**: {N} ({占比})
- **平均推理时间**: {N}s | **平均裁判时间**: {N}s（如有）
- **平均 Completion Token**: {N} | **平均 Prompt Token**: {N}（如有）

**典型 Badcase 分析**:

**Case #N** (question_id={ID})
- **问题**: {简述，不超过100字}
- **Score**: 0
- **Token 消耗**: completion={N}, prompt={N}, LLM calls={N}
- **错误原因**: {具体分析，1-2句话}

{评测集小结，1-2句话总结}

---

## 3. Badcase 归因分析

### 3.1 按评测集分布

| 评测集 | Badcase 数 | 占比 | 主要错误类型 |
| :--- | :--- | :--- | :--- |

### 3.2 模型能力短板总结

| 短板 | 证据 | 严重程度 |
| :--- | :--- | :--- |
| {描述} | {数据引用} | {🔴高 / 🟡中 / 🟢低} |

### 3.3 平台/环境问题

| 问题 | 评测集 | 影响 |
| :--- | :--- | :--- |

---

## 4. 建议与改进方向

1. {建议一}
2. {建议二}

---

*报告由 Taiji 评测深度分析系统自动生成*
```

**3.A 固定约束：**

- 报告章节固定为 4 个：`1.总体概览` / `2.各评测集详细分析` / `3.Badcase归因分析` / `4.建议与改进方向`，不可增删
- `1.0 评测集汇总表`：列固定为 8 列，不可增减；ACC/bon_acc/Error Rate/截断率 必须颜色标记；无该字段填 `-`
- `1.1 关键指标摘要`：行固定为 5 行，不可增减
- `2.{序号}` 每个评测集一个子节；有 badcase 逐条按 **Case #N** 格式展示；无 badcase 则"典型 Badcase 分析"替换为 `该评测集无 badcase。`
- **无 badcase 特殊处理**（全部 ACC=100%）：`2.` 每子节写"无 badcase，跳过详细分析"；`3.` 整节替换为一句 `无 badcase，所有评测集均满分通过。`；`4.` 正常填写

### 3.B 多模型对比报告模板

> 适用于多个模型在同一批评测集上的横向对比。核心差异：指标表按模型分列、Badcase 按同一 question_id 跨模型对照展示。以下代码块内即为报告正文模板：

```
# 多模型横向对比分析报告

> **分析时间**: {YYYY-MM-DD}
> **对比模型数**: {N}（已纳入对比的正常任务数；部分异常时仅统计正常任务）
> **参与对比的任务**: {task{id1}={模型A名称}, task{id2}={模型B名称}, ...}（仅列正常任务，模型名称保留完整，不截断）
> **共同评测集**: {共同评测集名称列表}
> **异常任务**: {task{id}={模型名}: {异常原因} / 无}

---

## 1. 总体对比概览

### 1.1 各评测集 ACC 对比

| 评测集 | {模型A} | {模型B} | {模型C} | 领先模型 |
| :--- | ---: | ---: | ---: | :--- |
| {评测集名} | {颜色标记} | {颜色标记} | {颜色标记} | {模型名} |

### 1.2 综合对比摘要

| 指标 | 数值 |
| :--- | :--- |
| 共同评测集数 | {N} |
| 整体领先模型 | {模型名}（在 {N} 个评测集上领先） |
| 分歧题总数（部分模型对、部分错） | {N} |
| 共性失败题总数（所有模型都错） | {N} |

---

## 2. 分歧 Case 对照分析

### 2.{序号} {评测集名称}

**Case #N** (question_id={ID})
- **问题**: {简述，不超过100字}
- **各模型表现**:
  - {模型A}: Score={0/1} — {回答要点摘要，不超过80字}
  - {模型B}: Score={0/1} — {回答要点摘要，不超过80字}
  - {模型C}: Score={0/1} — {回答要点摘要，不超过80字}
- **差异归因**: {为什么有的模型对、有的错，1-2句话；指出哪个模型处理更优及原因}

---

## 3. 共性失败 Case

| question_id | 评测集 | 可能原因 |
| :--- | :--- | :--- |
| `question_id={ID}` | {评测集名} | {题目歧义 / 难度过高 / 平台环境问题 等} |

---

## 4. 模型优劣总结

| 模型 | 优势领域 | 短板领域 | 综合评价 |
| :--- | :--- | :--- | :--- |
| {模型A} | {擅长的评测集/能力} | {薄弱的评测集/能力} | {🥇领先 / 🥈中等 / 🥉落后} |
| {模型B} | ... | ... | ... |

---

## 5. 选型建议

1. {场景/能力维度}：推荐 {模型名}，因为 {数据支撑}
2. ...

---

*报告由 Taiji 评测深度分析系统自动生成*
```

**3.B 固定约束：**

- 报告章节固定为 5 个：`1.总体对比概览` / `2.分歧Case对照分析` / `3.共性失败Case` / `4.模型优劣总结` / `5.选型建议`，不可增删
- `1.1 各评测集 ACC 对比`：列 = 「评测集 + 每个模型一列 + 领先模型」，模型列数随参与对比的模型数量动态扩展；ACC 用颜色标记；领先模型 = 该评测集 ACC 最高者，并列时全部列出；某模型无数据填 `-`
- `2. 分歧 Case`：优先展示分歧题（部分模型对、部分错）；每条 case 必须标注 `question_id`；各模型回答必须并列展示；分歧题超过 20 条时按差异类型归并，每组至少保留 1 条代表性 case
- `3. 共性失败 Case`：所有模型都得 0 分的题目；若无则写 `无所有模型均失败的 case。`
- `4. 模型优劣总结`：每个参与对比的模型一行；优势/短板需引用具体评测集或 case 数据支撑
- **部分异常时**（个别 task 被排除）：`对比模型数`和`参与对比的任务`只统计正常任务；`异常任务`元信息行列出被排除的 task 及原因；`1.1 汇总表`中异常 task 无列；`2/3/4` 章节只分析正常 task 之间的对比

---

## 4. 排版规则（强制执行）

1. 章节之间用 `---` 分割线分隔
2. 段落之间空一行
3. 百分比保留两位小数（如 `73.20%`），Error Rate 保留两位小数（如 `0.40%`）
4. 大数加千分位（如 `1,512,242`）
5. ID、工具名、评测集名用反引号包裹（如 `question_id=240289700`、`tool_error`、`dop_test/general`）
6. 模型名称保留完整，不截断
7. question_id 展示格式统一为 `question_id={ID}`（不要用 = 号或空格）

---

## 5. Badcase 展示规范

- 所有 avg_score=0 的 case 必须逐条展示
- 格式固定为上方 **Case #N** 模板
- 若 badcase 超过 20 条，可按错误类型归并，但每组至少保留 1 条代表性 case 的 `question_id`
