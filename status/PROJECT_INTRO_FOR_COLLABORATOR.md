> 日期:2026-06-29。

---

## 1. 一句话

我们研究**大模型的长程记忆**:把超长文档压进一个固定大小的记忆,之后回答问题。我们发现长程记忆的瓶颈不是"记不下",而是**"记下了但读不出来"**——并提出一个反直觉但有效的读出方式,在干净评测上显著超过现有方法。

---

## 2. 背景与设定

- **任务**:BABILong —— 把答案线索("needle")藏进 0–32k token 的长文档,模型读完后回答问题(qa1 单事实 / qa2 双事实推理 / qa5 关系推理)。
- **骨干**:Llama-3-8B(冻结),外挂一个记忆模块。
- **记忆机制**:文档切成 512-token 的 chunk,流式读入,每个 chunk 的隐状态(hidden)存进一个**逐层的固定大小记忆**(per-layer FIFO buffer,或压缩成少量 slot)。回答时从记忆里读。
- **干净性红线**:很多历史结果因为训练数据混入了评测集而虚高;我们严格只用 `mix=0` 的干净 checkpoint,**真 SOTA 锚点 = pg19 蒸馏的 qa5 16k=16 / 32k=9**。

---

## 2.5 两种记忆方法长什么样(给新读者)

我们项目里有两族记忆实现,本文反复提到它们,先讲清运作方式。两者骨干都是**冻结的 Llama-3-8B**——只在每层插一个记忆模块,文档按 512-token 的 chunk 流式喂入。

### (A) Memory Slots(压缩式,我们的"slot")
每一层维护一组 **128 个 slot 向量**(每个就是一个 d=4096 维的隐向量,和 backbone hidden 同维)。它们是一块**固定大小的"工作记忆白板"**:

- **写入**:每读完一个 chunk,一个小的**选择器**(selector:两个投影 Q_sel/K_sel + softmax 打分)给 128 个 slot 打分,选出 **top-16** 个最相关的 slot,把这个 chunk 的内容(对 chunk 内 token 聚合后)**以 EMA 方式更新**进这 16 个 slot。即:slot 不是堆叠存储,而是**少量槽位被不断覆盖改写**——这就是"压缩"(几千个 token 的信息被挤进 128 个槽)。
- **读出**:回答时,问题同样经选择器路由到 top-16 个 slot,这些 slot 向量作为**前缀**参与注意力,模型从中读信息。
- **关键性质**:slot 是**有损压缩**(token 数被压缩、且写入时问题还没出现),所以"存了粗略语义、丢了精确细节"。
- 选择器用 STE(直通估计)保持可微,可端到端训练;带 load-balance 损失防止所有内容都挤进同几个槽。

### (B) FIFO hidden buffer(无损式,我们的主线)
每层维护一个**先进先出队列**,直接存最近若干个 chunk 的**原始 hidden 快照(不压缩,1:1)**,超出容量(默认 25 个 chunk)就丢最老的。读出时对 buffer 里的 hidden 做注意力。
- 它和 slot 的区别:**不压缩**(存的是原 hidden),但容量有限(只留最近 25 块)。
- 我们破读出墙的主线实验用的是这一族(配下文的 token re-forward)。

### (C) "MemoryLLM-like"是什么意思
学界代表方法 **MemoryLLM**(及后续 M+)走的是 **compress-then-inject** 路线:把过去内容压成少量 latent memory token(类似我们的 slot),回答时把这些 memory **作为 KV 前缀注入**冻结模型——**全程不重新读原文**。我们项目里也实现并测过这种"注入"式读出(内部叫 Method A / raw-KV inject)。**本文后面说的"注入(inject)"就指这种**——它是我们方法的对照组(见第 5、6 节)。

> 一句话区分:**slot = 压缩白板**(少量槽位反复覆盖);**FIFO = 无损近窗**(留最近几块原 hidden);**inject = 把记忆当 KV 喂进去,不重读原文**;而我们主张的 **re-forward = 把选中的原文重新跑一遍**(下文核心)。

## 3. 核心发现:两堵墙

我们把长程记忆的失败**分解成两个可独立测量的瓶颈**:

### 墙一:读出墙(read-out wall)—— 已找到破法
**现象**:纯从记忆 hidden 读出(我们记作 **W0**),即使"完美隔离"出含答案的那一块,也只到 **~20-24**(qa5 8k)。**记下了,却读不出。**

**根因**:记忆里存的是 chunk **当初被读入时**算的 hidden 快照——那时**问题还没出现**,所以这份快照是"query-blind"的,丢了回答所需的精确绑定。

**破法 = token re-forward**:不读冻结的 hidden 快照,而是把选中 chunk 的**原始 token** 连同问题**重新前向跑一遍整个模型**。这样原文在"问题在场"下被重新理解。
- **效果【已确证】**:qa5 8k 从 W0 的 12 → **66**(oracle,即完美选中时)。读出墙被打破。

### 墙二:选择墙(selection wall)—— 短档已解,长档进行中
既然读出靠"重读选中的 chunk",那**选哪些 chunk**就成了关键。
- **短档(8k,候选少)【已确证】**:训练一个轻量选择器,可部署精度从零训练的 28 → **46**(qa5 8k),逼近完美选中的 66。
- **长档(16k/32k,候选多)【进行中】**:候选 chunk 多到 25-64 个时,现有选择器(reader-attn / slot 路由)都**选不准**(needle recall 接近随机)。**完美选中的上界明明有 50-52(oracle),但现有选择够不着**——这是我们当前主攻的开放问题。

---

## 4. 主要结果(干净,满 100 样本)

**可部署系统**(训练选择器 + token re-forward,K=4):

| qa5 | 8k | 16k | 32k |
|---|---|---|---|
| **我们(部署)** | **52** | **38** | **32** |
| 真 SOTA 锚点(pg19) | 19 | 16 | 9 |
| 完美选中上界(oracle) | 66 | 52 | 50 |

**长档上比干净 SOTA 锚点高 2.4–3.6×,且无数据泄漏。** oracle 行说明长档还有头寸(部署 vs 上界仍有 14-18 分差距 = 选择墙)。

---

## 5. 与 MemoryLLM 的关系(范式对比)

这是我们方法的定位锚点(已联网核实其论文):

| | **我们:select-then-reforward** | **MemoryLLM:compress-then-inject** |
|---|---|---|
| 存什么 | 原始 token(无损) | 压缩的 latent memory token |
| 怎么读出 | 选中 chunk 的原 token **重新前向**(问题在场) | memory 作 KV 前缀**注入**(问题缺席时写入) |
| 选择 | 训练的 chunk 选择器 | 无显式选择 |

**关键证据**:我们实测了 MemoryLLM 式的"注入"(把正确证据作 KV 注入冻结模型)——干净增益只有 **+1~2.5**。正是因为注入读不出来,我们才转向"重读原文"。**两者是相反的范式,而我们有数据证明在这个任务上重读 > 注入。**

---

## 6. 中心论点:存储有效,读出是瓶颈

我们在**两种记忆架构 × 两种读出方式**的四个组合上都看到同一现象:**"加原始 token 重读" 远好于 "纯压缩读出"**:

| | 纯压缩读出(W0) | 加原 token 读出 |
|---|---|---|
| **slot 压缩记忆** | qa5 8k ≈ 12-16 | + SWA → 34-54 |
| **FIFO hidden 记忆** | qa5 8k ≈ 12 | + reforward → 66 |

四个象限一致 → **"记忆确实存住了长程信息,瓶颈在读出而非存储"是架构无关的共性**,不是某个实现的偶然。这是论文的中心论点。

---

## 7. 贡献总结

1. **诊断框架**:把长程记忆失败分解为可独立测量的**读出墙 + 选择墙**(配 oracle 探针定位上界)。
2. **token re-forward**:破读出墙的机制——重读原文 >> 注入压缩记忆(实测 inject 仅 +1-2.5)。
3. **干净 SOTA**:可部署系统在长档达 2.4-3.6× 于干净锚点,匹配 teacher 水平,**无泄漏**(我们还顺带厘清了项目历史上大量被数据泄漏虚高的结果)。
4. **诚实的负结果 + 开放问题**:长档选择墙——完美选中头寸存在(oracle 50-52),但现有选择器够不着;这是清晰的下一步。
